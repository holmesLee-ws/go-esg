# 성숙도 판정

## 수준

go-* 시리즈 공통의 네 수준을 쓴다(go-develop이 쓴 CS2023 숙련 수준과 같은 이름). Explain이 나머지의 선행 수준이다.

| 수준 | 이름 | 증거 |
|---|---|---|
| 0 | 미접촉 | 없음 |
| 1 | Explain | 자기 말로 설명하고, 왜 그런지 말한다 |
| 2 | Apply | 처음 보는 사업장·거래 상황에서 직접 분류·산정·적용하고, 결과를 예측한다 |
| 3 | Evaluate | 선택지를 비교해 근거와 함께 결정한다 |
| 4 | Develop | 제약(일정·자료·인력)이 있는 실제 과제에 업무 산출물을 설계해 만들어 낸다 |

## 증거의 무게

- 자기 신고는 어디부터 물어볼지 정하는 데만 쓴다. 숙달의 근거가 아니다.
- 탐침과 과제의 결과만 수준을 올린다.
- 정의나 시행 일정을 외워 답한 것은 증거가 아니다. 그 지식으로 상황을 판단해야 증거다.

## 탐침 만드는 법

- 그 모듈의 목표 수준에 맞춘다. 정의를 묻지 않고 처음 보는 상황(학습자 업종의 사업장, 거래처 요청, 공시 초안 문장)에서 분류·판단·진단하게 한다.
- 시행일·기준값을 맞히게 하는 탐침은 내지 않는다. 그런 값이 상황에 필요하면 근거 규칙대로 확인한 값을 문제에 주고 판단을 묻는다.
- 힌트를 주지 않고 짧게 답할 수 있게 낸다. 탐침은 예측·진단·수정 중 하나만 묻는다. 덧붙일 수 있는 것은 「이유」 하나뿐이다. 원인과 고치는 법은 다음 차례로 나눈다. 페이지 조작을 부탁한 차례에는 새 문제를 내지 않는다.
- 빠진 개념의 이름을 말한 뒤 내는 문제에는 그 개념의 판정 값(예: 비교할 수익률·기준선)을 주지 않는다. 무엇과 비교할지 학습자가 스스로 꺼내게 한다.
- 판정 기준을 내기 전에 정한다. 결론만 맞고 이유가 틀리면 맞음이 아니다.

## 판정 절차

모듈당 탐침은 최대 3개, 판정까지 3차례를 넘기지 않는다.

| 결과 | 경로 | 기록 |
|---|---|---|
| 목표 수준 탐침 2개 정답(입구 진단에서 그 모듈을 직접 다룬 정답도 1개로 센다) | 건너뜀. 한 줄로 알리고 다음으로 | `status: verified_skip`, 달성 수준, 증거 |
| 하나 정답, 하나 부분 정답 | 빈틈만 다룬다 | `status: in_progress`, `gaps`에 빈틈 |
| 첫 탐침 오답이나 「모르겠어요」 | 한 단계 낮춰 다시 묻거나 전체 경로로 | `status: in_progress` |
| 학습자가 그냥 넘어가겠다고 함 | 바로 넘어간다. 돌아올 수 있다고만 말한다 | `status: self_skip`, 증거 없음 |
| 그 외(정답과 오답, 부분 정답 둘 등) | 빈틈만 다룬다 | `status: in_progress`, `gaps`에 빈틈 |
| 학습자가 「처음 본다」고 함 | 탐침을 생략하고 풀이 예시부터 보여 준다 | `status: in_progress`, 시작 수준 0 |

- 「다 알아요」는 사실 진술이므로 강의하지 않고 곧바로 목표 수준 탐침을 낸다. 「건너뛰죠」는 결정이므로 바로 `self_skip`으로 넘어간다. 둘이 함께 나오면 결정을 따른다.
- 학습자가 시간을 쓰겠다고 말한 모듈은 탐침을 맞혀도 자동으로 건너뛰지 않고, 건너뛸지 더 깊이 볼지 묻는다.
- 목표가 Develop인 모듈(지도에서 목표가 Develop인 것과 X1)은 짧은 탐침으로 건너뛰지 않는다. 학습자가 실제 업무에서 이미 만든 결과물(익명화한 것)을 함께 검토해서만 건너뛴다.
- `self_skip`과 `estimated`는 숙달이 아니다. 그 모듈이 선수인 모듈을 시작할 때 핵심을 탐침 1개로 확인한다.
- 탐침에서 드러난 빈틈이 다른 모듈에 속하면 `gaps`에 기록하고, 지금 흐름에 필요한 만큼만 메운다.

## 영역 빠른 확인

학습자가 영역 전체를 빠르게 확인하고 싶어 하면, 뒤쪽의 심화 모듈부터 탐침한다. 빠른 확인 중인 모듈은 위 판정 표 대신 이렇게 닫는다. 첫 탐침이 정답이면 다른 맥락의 탐침 하나를 더 내고, 맞히면 `verified_skip`이다. 부분 정답이면 빈틈 이름을 한 줄로 말하고 다른 맥락의 빈틈 탐침을 **딱 1회** 낸다. 맞히면 `verified_skip`(증거에 그 답 인용 포함), 못 맞히면 `gaps`에 적고 `estimated`로 둔다. 오답이면 `gaps`에 적고 `estimated`로 둔다. 어느 쪽이든 모듈당 튜터 응답 3번 안에 닫고 다음 모듈로 가며, 빈틈 비트·도식은 학습자가 그 모듈을 고를 때 한다. `inferred`의 근거는 `verified_skip`뿐이다(`done`에서도 추론하지 않는다). `verified_skip`이 된 모듈의 선수 모듈만 `inferred`로 기록하고 다시 묻지 않는다. `inferred`의 `level`은 상위 모듈 수준을 복사하지 않고 그 모듈 목표 수준의 바로 아래까지만 적으며, 증거에 「추론: ○○ 통과」라고 밝힌다. 탐침 1개만 맞은 `estimated` 모듈로는 추론하지 않는다. 튜터도 입구 진단 뒤에 이 확인을 먼저 제안할 수 있다.

## 복습 간격

인출 연습과 분산 학습이 학습 기법 중 효용이 가장 높게 평가되었으므로(Dunlosky 외, 2013) 복습을 넣는다.

- 완료 시 `review_step: 0`, `review_at`은 1일 뒤로 둔다.
- 복습에 성공하면 간격을 3일, 7일, 21일로 늘린다. 21일 복습에도 성공하면 `review_at`을 `null`로 둔다.
- 실패하면 `review_step`을 0으로 돌리고 빈틈을 `gaps`에 적는다.
- 복습은 세션 시작 시 1개만 낸다. 새로운 상황으로 바꿔 묻는다.
- `verified_skip`은 복습 대상이 아니다.

## 기록 형식

`learner/state.json`의 `modules`에 모듈 id를 키로 둔다.

```json
"C2": {
  "level": 2,
  "status": "done",
  "evidence": ["2026-11-14 물류 위탁 운송 배출 분류 — 답: \"우리 차가 아니니까 스코프 3, 다만 리스 차량이면 따져 봐야\""],
  "review_at": "2026-11-15",
  "review_step": 0
}
```

`status`는 `estimated`, `inferred`, `in_progress`, `done`, `verified_skip`, `self_skip` 중 하나다. `inferred`는 상위 모듈을 통과해 추론한 것으로 다시 탐침하지 않는다.

출제와 채점을 튜터 혼자 하므로, `evidence`에는 판단만 적지 않고 **학습자의 답을 짧게 인용한다.** 따옴표 안은 대화에서 그대로 복사한다. 구절을 잇거나 조사·어미를 바꾸지 않고, 줄일 때는 `…`를 쓴다. 바꿔 쓰려면 따옴표 밖 요약으로 쓴다. 앞부분을 자를 때도 `…`를 쓴다(예: 원문 「음… 없을 것 같아요」를 줄이면 "…없을 것 같아요"). 이 규칙은 HTML 페이지에 넣는 학습자 답 인용에도 똑같이 적용한다.

`gaps`는 객체 배열이다: `{"module": "C1", "at": "2026-11-14", "gap": "빈틈 한 줄", "quote": "학습자 답 인용(선택)"}`. 문자열만 넣지 않는다.
